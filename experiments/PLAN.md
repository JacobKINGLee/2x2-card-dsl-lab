日期：2026-09-07。状态：v1 第一轮完成；v2 语义协议、规则接线、分层评分、离线校准和 12 条冻结新输入预检完成，停在“首次用新输入重跑 Qwen”之前。

## v2 重评准备状态

新链路为 `自然语言 → SemanticDocument 2.0 → 组件规则＋宿主能力 → DSL → 布局交付门禁`。规则层函数不接受原句。模型 Schema 不包含组件、可执行事件、应用资源或布局字段。

评测已拆为模型理解、人工确认语义的规则决策、模型输出端到端三层，并单列正确出卡、错误出卡、合理非出卡与最终可交付状态。开发校准集不具独立性，Qwen 运行器会拒绝未显式传入或未声明 `independent=true` 的数据集。`independent-v2.mjs` 已通过无模型预检；尚未发出真实 Qwen 请求。执行步骤见 `EVALUATION_V2.md`。

以下章节记录 v1 实验计划与结果边界，不作为 v2 当前接口说明。

## 目标和边界

使用用户提供的阿里云专属 OpenAI 兼容 API 调用 `qwen3-8b`，评估其将中文自然语言转换为当前 Semantic Plan，并经现有编译、布局和视觉引擎生成卡片的能力。云 API 结果只能作为小模型语义能力代理；不能用于推断端侧量化精度、内存、功耗或设备推理速度。服务实际权重、精度和硬件未知，记录响应 model 字段。

第一轮冻结现有 Semantic Plan：8 个 domain、3 个主视觉组件、单主指标和一个按钮。不修改协议来适配模型结果。多指标、无按钮、缺失核心数值、相互矛盾和非卡片请求作为单独的边界探针，不混入正常场景的分母。

## 执行步骤

1. 核验接口与模型标识；选择可用的结构化输出方式，保留探针原始响应。
2. 建立 120 条固定正常场景（40 个语义案例 × 3 种表达）及 12 条边界探针；在正式模型调用前冻结输入和预期值。预期由人工编写的事实断言组成，接受语义等价的值；本轮为工程师/AI辅助初评，仍需独立人工复核。
3. 接入独立可复跑评测器，保留请求配置、原始响应、严格 Schema 校验、归一化差异、DSL 和布局质量结果。评测禁止静默规则回退和模型重试。
4. 跑当前规则解析器和 Qwen3-8B；若本机已有可用 openPangu 配置则跑同集云端基线，否则明确标为未测，不能沿用布局压力测试充当云模型成绩。
5. 检查典型失败，输出分组结果与限制；同源三种改写按同一案例族解释，不视为 120 个独立语义问题。
6. 后续根据错误类型决定协议精简、约束解码或微调。在未参与提示调整的独立保留集上复测；模型效果合格后再进入目标设备实测。

执行中增加一轮有界对照：基线开发样本已暴露枚举含义不清、actionEvent使用下划线、组件选择违背协议。增加 `explicit-v1` 提示，把现有撰写指南的领域映射、组件规则、单位与事件格式写清楚；不改 Schema、数据或评分。两套配置各跑一次同集并保留全部结果。现有24条预留分组与开发集共享领域和表达模板，不能视为独立泛化盲测；后续仍需新的人工盲测集。

## 指标

- HTTP 成功率和原始 JSON / Schema 合法率，二者分别报告。
- 领域、组件、核心值/单位/进度、显式状态与强调、操作事件等预设断言通过率；不以整段文案字符串相等打分。
- 归一化修复率、DSL 校验率、引擎质量门禁通过率和关键字段+Schema+门禁联合通过率。
- 原始样本和失误清单供人工复核：自动断言不等于完整语义正确率，文案幻觉和遗漏仍需检查。
- 单请求完成时间 p50/p95、tokens 和并发配置；标注为云端网络+排队+推理总延迟，不作为端侧性能。
- 边界探针单列协议缺口和模型表现；不将被迫补默认值算作正确拒绝。

## 暂定决策门槛（非实测结果）

正常场景原始 Schema 合法率 ≥99%，关键语义断言通过率 ≥95%，联合通过率 ≥95%；重要数值或操作错误逐个审查。这些仅用于下一轮实验决策，不代表上线标准。端侧延迟与内存预算需在设备规格确定后制定。
